A **gig** is the central record for everything that happens around one engagement: when and where it is, who's working it, what's on the schedule, and what's owed. Whether your team calls them shows, events, or performances, gigs are where live work lives in Soundcheck. This page walks you through the Gigs board, the tabbed detail inside each gig, and the lifecycle every gig moves through from first draft to final settlement.

## The Gigs board

The **Gigs** board is where every show lives. Four **stat tiles** at the top give you a quick read on your operation:

| Tile | Shows |
|---|---|
| **Active** | Gigs currently in production. |
| **Draft** | Gigs still being prepared. |
| **Pending invites** | Crew replies you're still waiting on. |
| **Upcoming payout** | Unsettled team costs ahead. (Crew members see **Upcoming pay** — their own unsettled pay.) |

Below the tiles, a sticky filter bar lets you search by title, venue, or city, and filter by date range, status, and event type.

### Three ways to view your gigs

<Tabs>
  <Tab title="Table">
    A dense, sortable table — **Gig, Type, Date, Venue, Confirmed, Payout, Status** — for scanning many gigs at once. This is the default view.
  </Tab>
  <Tab title="Card">
    Gigs displayed as cards, split into **Happening today**, **Upcoming**, and **Past** sections. Tours appear as collapsible folder rows at the top of this view.
  </Tab>
  <Tab title="Calendar">
    Your gigs laid out on a month calendar for a schedule-first perspective.
  </Tab>
</Tabs>

Each gig card shows the title, venue, status pill, event type, and date (a range for multi-day gigs). Managers see a **Team confirmed** progress bar and the gig's total payout. Crew members see their position and their own pay.

## The gig detail

Open any gig to work it. The detail page is organized into tabs so every aspect of the show has its own space:

| Tab | What it holds |
|---|---|
| **Details** | The core record: Run of Show, day-of timeline, attachments, notes, setlist, location, and team. |
| **Tasks** | The pre-show checklist of everything that has to happen before doors. |
| **Venue** | The venue record and per-show logistics (load-in, parking, access). |
| **Inventory** | Gear and resources assigned to the gig. |
| **Files** | Documents on the gig, including AI file ingestion where enabled. |
| **Finances** | Payables and crew payouts. (Crew see **My Expenses** — their own.) |
| **Clients** | Customers and sponsors tied to the gig. |
| **Activity** | The gig's full audit log of who changed what and when. |
| **Closeout** | The post-event checklist, settlement controls, and reviews. |

<Note>
  Tabs appear based on your role and your organization's enabled features. A gig coordinator staffing a show sees a different set than an owner settling the books.
</Note>

The **Details** tab is the working center. The Run of Show sits pinned at the top, and the sections below it — timeline, attachments, notes, setlist, location, and team — can be rearranged to fit how you work.

### Open Items

Every gig header includes an **Open Items** chip that counts what still needs doing: unanswered invitations, unsigned contracts, unpaid payouts, and overdue tasks. Tap the chip to jump to the specific items and clear them before the show. The same open items roll up across your entire operation in **Rounds** on the Home page, ordered by urgency.

## The gig lifecycle

Every gig moves through a defined set of states. Most follow the path **Draft → Active → Completed → Settled**. Two additional states — **Cancelled** and **Archived** — cover gigs that don't reach settlement. **Template** holds reusable gig structures you can spin up new drafts from.

| Status | What it means |
|---|---|
| **Draft** | Being prepared; sends no notifications on its own. Publish it to go live. |
| **Active** | Live for staffing, scheduling, contracts, and crew notifications. |
| **Completed** | Set automatically once the event date passes; moves the gig into closeout. |
| **Settled** | Every payout has cleared and the gig is fully closed on the books. |
| **Cancelled** | The gig was called off (from Draft or Active); never gated by closeout. |
| **Archived** | A legacy filing state for delivered gigs that predate the Settled workflow. |
| **Template** | A saved gig structure for spinning up new drafts with pre-built crew and schedule. |

<Info>
  You never manually move a gig to **Completed** — Soundcheck does that automatically when the event date passes. You do control the move from Completed to **Settled**, which is gated by payout clearance and your org's close-out checklist.
</Info>

## Tours: grouping related gigs

A **Tour** is a folder that groups related gigs on the Gigs board — a spring run, a festival weekend, a venue residency — so you can manage the run as a whole. Tours appear as collapsible folder rows at the top of the Card view and roll up **revenue, payouts, and net** across every gig inside, giving you a P&L view of a whole run without opening each gig individually.

Add existing gigs to a tour, or create a new gig directly inside one. A gig belongs to one tour at a time. Deleting a tour returns its gigs to the ungrouped list — the gigs themselves are never deleted.

## Who can manage gigs

| Action | Owner | Admin | Gig Coordinator | Member |
|---|:---:|:---:|:---:|:---:|
| View gigs | ✓ | ✓ | ✓ | Invited only |
| Create and edit gigs | ✓ | ✓ | ✓ | No |
| Staff the team | ✓ | ✓ | ✓ | No |
| Send payouts and settle | ✓ | ✓ | No | No |
| Respond to invitations | ✓ | ✓ | ✓ | ✓ |

<Note>
  Gig Coordinators run the operational side — creating, staffing, and scheduling — without payout or P&L access, which stays with Owners and Admins.
</Note>

## Web vs. mobile

Both surfaces show the same gig data. Build-and-configure work lives best on web; in-the-moment work lives on the mobile app.

| Action | Web | Mobile |
|---|---|---|
| Create a gig | Full form | Light (title, date, venue) |
| Build and manage the team | Full | Read and respond |
| Edit Run of Show and timeline | Full | Read; light edits |
| View tonight's setlist | Yes | Yes (cached for offline) |
| Chat with the team | Yes | Yes (native push) |
| Send payouts | Yes | No |

See [Mobile app overview](/features/mobile/overview) for the full parity table.
