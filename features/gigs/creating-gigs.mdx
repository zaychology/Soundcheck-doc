Creating a gig in Soundcheck is intentionally fast: a name and a date are all you need to get a record on the board. Everything else — venue, crew, setlist, contracts, files — comes afterward from the gig's tabbed detail page. This guide walks you through the create form, optional fields, and the faster paths for recurring gig structures.

## Create a new gig

You can open the create form from the **Gigs** board or from **Home**. Both paths create an **Active** gig and land you on the new gig's detail page, ready to build.

<Steps>
  <Step title="Open the create form">
    On the **Gigs** board or **Home**, choose **Create gig**. The **Create new gig** dialog opens.
  </Step>
  <Step title="Name the gig">
    Enter a **Gig name**. This is the only truly required field. Use something your team will recognize at a glance — for example, *"Johnson Wedding, Grand Ballroom"* or *"Riverside Festival – Main Stage."*
  </Step>
  <Step title="Set the date">
    Pick the **Date**. It defaults to today. For a multi-day run — a festival weekend or a two-night engagement — also set an **End date** (see [Multi-day gigs](#multi-day-gigs) below).
  </Step>
  <Step title="Choose the event type">
    Select a **Gig type** to categorize the show. Options include **Wedding, Church, Private Gig, Corporate Gig, Bar/Club, Rehearsal, Festival, Concert,** and **Other**. The type defaults to *Wedding* and is used for filtering on the Gigs board.
  </Step>
  <Step title="Add a location (optional)">
    Start typing in the **Location** field and pick a venue from the address-search suggestions. Soundcheck captures the place name, formatted address, and map coordinates so the crew gets accurate directions. Location is optional — you can create a gig before the venue is confirmed and add it later.
  </Step>
  <Step title="Create">
    Choose **Create**. You land on the new gig's detail page. If you created an empty gig, Soundcheck automatically attaches your organization's **Standard Show** run of show and **Standard Tasks** checklist, so Details already has a framework instead of blank pages.
  </Step>
</Steps>

<Note>
  A new gig created from the form launches as **Active** and appears on your board and calendar right away. If you need it to start as a **Draft** — for example, to finish building it before anything goes out — create it from a template instead (see [Start from a template](#start-from-a-template) below).
</Note>

## All gig fields

| Field | Required | Notes |
|---|---|---|
| **Gig name** | Yes | The gig's title as it appears on the board and in notifications. |
| **Organization** | Yes | Defaults to your active organization; change it if you belong to more than one. |
| **Gig type** | Yes | Defaults to *Wedding*. Used for board filtering. |
| **Date** | Yes | Start date. Defaults to today. |
| **End date** | No | For multi-day gigs only. Must be on or after the start date. |
| **Location** | No | Address search with map integration. Add a saved venue record from the Venue tab after creating. |
| **Department** | No | Appears only when your organization uses departments. |

## Multi-day gigs

For any engagement that spans more than one calendar day — a festival, a multi-night residency, a weekend conference — set an **End date** alongside the start **Date**. Multi-day gigs show their full date range on the Gigs board card.

<Info>
  An overnight show that ends in the early morning is still a single-day gig. When an out time is earlier than the call time (for example, 8:00 PM – 2:00 AM), the **Past midnight (next day)** toggle handles it automatically. You don't need an End date for overnight shows.
</Info>

To group several *separate* shows into one run with a shared financial roll-up, use [Tours](/features/gigs/overview) instead of a multi-day date range.

## Adding a venue with map integration

The **Location** field is an address search powered by map data. Soundcheck stores the place name, formatted address, and coordinates so crew members get a map pin directly to the venue.

<Steps>
  <Step title="Start typing the venue name or address">
    Begin entering the venue's name or street address in the **Location** field.
  </Step>
  <Step title="Select a suggestion">
    Pick the correct match from the dropdown list.
  </Step>
  <Step title="Coordinates save automatically">
    The map location is stored with the gig. Crew members on mobile can tap the address to open it in their maps app.
  </Step>
</Steps>

<Tip>
  The Location field captures *where* the gig is. To link a **saved venue record** — with reusable load-in notes, parking details, access instructions, and per-show overrides — open the gig's **Venue** tab after creating it. That's where venue-specific logistics live for the crew.
</Tip>

## Adding notes and files

Once the gig is created, use the **Details** tab to add context your team needs:

- **Notes**: Free-text notes visible to the assigned team. Add production details, client preferences, dress code, or anything relevant to the show.
- **Attachments**: Upload stage plots, tech riders, venue maps, contracts, and other files via drag-and-drop or the file browser. The entire assigned team can view and download attachments on both web and mobile.

## Saving as Draft vs. publishing to Active

A gig created through the standard form starts as **Active** immediately. Active gigs appear on the board, are visible to your team, and can receive staffing and notifications right away.

To keep a gig hidden while you're still building it, use one of these paths instead:

| Path | Result |
|---|---|
| **Create from a template** | Creates a **Draft** you review and publish when ready |
| **Duplicate an existing gig** | Creates a **Draft** copy you can edit before publishing |
| **Standard create form** | Creates an **Active** gig immediately |

Publish a Draft to Active by tapping the **Draft** status pill in the gig header and selecting **Set to Active**. See [Gig lifecycle](/features/gigs/overview) for the full status progression and what each state means.

## Using templates to spin up repeated structures

If your organization runs the same type of show repeatedly — a recurring corporate event, a weekly club set, a standard wedding format — templates let you save that structure once and reuse it on every new gig.

<Steps>
  <Step title="Open Templates">
    On the **Gigs** board, navigate to the **Templates** section.
  </Step>
  <Step title="Choose a template">
    Select the template that matches the show you're booking.
  </Step>
  <Step title="Use template">
    Choose **Use template**. Soundcheck creates a new **Draft** gig pre-loaded with the template's run of show, standard crew positions, tasks, and any attached files.
  </Step>
  <Step title="Set the date and customize">
    Update the gig name, date, and venue. Times in the run of show re-anchor to the new date automatically. Add or adjust positions, then publish to Active when the gig is ready.
  </Step>
</Steps>

<Tip>
  To save a gig you've already built as a template for future use, open the gig's Run of Show section, tap the **⋯** menu, and choose **Save as Template**. It copies every section, item, song, and attachment as it stands.
</Tip>

## Duplicating an existing gig

When a new gig closely resembles a past one, duplicating is faster than starting from scratch.

<Steps>
  <Step title="Open the source gig">
    Find the existing gig you want to copy on the Gigs board and open it.
  </Step>
  <Step title="Duplicate">
    Tap the **⋯** actions menu in the gig header and choose **Duplicate**.
  </Step>
  <Step title="Set the new date">
    The duplicate opens as a **Draft**. Update the name, date, and venue for the new engagement. Schedule times rebase to the new date automatically.
  </Step>
  <Step title="Review and send invitations">
    Copied invitations remain **unsent** until you send them. Review the team, make any changes, and send when the gig is ready to staff.
  </Step>
</Steps>

See [Using templates](#using-templates-to-spin-up-repeated-structures) and [Duplicating an existing gig](#duplicating-an-existing-gig) above for the full reference.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Can't find the venue in location search?">
    Location is optional. Create the gig first, then add the venue from the **Venue** tab once confirmed, or type the address manually.
  </Accordion>
  <Accordion title="Need to change the date after creating?">
    Open the gig, edit the date field, and save. If the date shifts significantly, check whether you need to resend team invitations with updated call times.
  </Accordion>
  <Accordion title="Created the wrong gig by accident?">
    You can delete it from the gig's **⋯** actions menu. Use caution deleting a gig that already has crew invitations or financial activity — deletion removes the historical record.
  </Accordion>
  <Accordion title="Want the gig to start as a Draft, not Active?">
    Use a template or duplicate an existing gig. Both create a Draft. The standard create form always produces an Active gig.
  </Accordion>
</AccordionGroup>
